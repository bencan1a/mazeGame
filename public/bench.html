Buffer Ceiling Bench

The renderer plan assumes two offscreen canvases can be held at once and one copied to the screen every frame. Neither half is measurable on a build server. This measures both, here, on this phone, using a real generated 100×100 board.

Ready.

1 · How large a single buffer will it give?

Allocates square canvases of increasing size and reads a drawn pixel back from each. Safari does not raise an error when it runs out — it returns a blank canvas — so the readback is the only reliable signal.

2 · Will it hold two at once?

The design keeps a static layer for idle segments and a second layer for the segment leaving. Both are live during an exit animation. This allocates the pair, then re-checks the first — iOS can blank a buffer it already gave you rather than refusing the new one.

3 · How fast does it copy?

Draws the board into the buffer once, then copies a moving, zooming crop of it to the screen for four seconds. 60 fps is a 16.7 ms frame budget.
